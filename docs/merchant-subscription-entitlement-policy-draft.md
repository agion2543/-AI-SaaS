# 商家订阅权益与到期访问规则草案

> 供业务决策使用。此文只记录当前代码行为和建议，不代表已确认的商业规则；本次没有修改代码、套餐授权或支付流程。结论来自本地源码审阅，不是生产或真实商家验证。

## 当前代码里已确认的行为

- 套餐目前只有名称、价格、服务周期和排序字段；没有每档功能权益、员工数或门店数上限。
- 商家端主要业务 API 使用统一订阅门禁：订阅必须为 `active`，且到期时间在未来。没有按套餐档位分开授权。
- 暂停/到期后，受保护的商家 API 会拒绝访问；页面壳是否仍能打开，不等于商家业务数据接口可用。当前没有单独设计“只读历史数据”模式。
- 已审核且有效的团购跳转入口由公开跳转服务处理；它检查商家/门店/链接状态和平台审核状态，但不检查订阅是否有效。因此单纯订阅到期并不会自动关闭已发布链接。
- AI 生产服务尚未接入，AI 功能目前对所有商家都不应宣传为可用的套餐权益。

## 建议规则与待定项

| 事项 | 当前行为 | 建议默认规则 | 需要决定什么 |
|---|---|---|---|
| 套餐档位功能 | 所有有效订阅共用同一套已上线功能；无分档门禁 | 暂时保持所有套餐共享已上线功能。等某项功能确实上线、且后端门禁做好后，再决定是否分档 | 以后是否需要按套餐限制功能、员工数或门店数？目前不做限制 |
| 暂停/到期后的数据访问 | 受保护 API 被统一拒绝；没有只读例外 | 建议暂停/到期后禁止新增和修改，但保留查看既有订单、经营记录和续费入口；若涉及敏感操作再单独限制。实施前需划清只读接口范围 | 是否接受只读查看，还是继续当前“业务 API 全部阻断”的严格方式？ |
| 已发布的团购链接 | 订阅到期不会自动停止公开跳转；平台审核/商家/门店/链接状态仍有效时可跳转 | 建议普通到期不立刻切断已印制的二维码；商家不能继续管理入口。平台因安全/资质原因暂停时，立即停止跳转 | 普通订阅到期时，链接继续可用还是停止？平台安全暂停继续优先停用 |
| AI 功能 | 生产服务禁用；不应计作已上线权益 | 对所有套餐统一标为“暂未接入”，不计入套餐权益；接入并完成验证后再决定档位 | 暂无业务选择；待真实接入后再讨论 |

## 执行顺序建议

1. 先确认前三项待定规则，AI 暂按“未接入、不属于套餐权益”处理。
2. 若决定开放到期后的只读访问，先补后端逐接口分类与权限测试，再调整前端页面；不只靠隐藏按钮。
3. 若未来要做套餐差异化，再新增明确的权益数据契约和服务端 enforcement，同一份配置同时驱动商家展示与 API 门禁。
4. 每项规则先用合成数据覆盖有效、暂停、到期、越权和恢复场景；真实商家验证、支付渠道和部署演练继续后置。
