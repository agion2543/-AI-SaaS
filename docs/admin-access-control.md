# 管理员权限与超管恢复

## 权限分组

后台普通管理员按岗位授予业务权限：**只读查询**查看经营概览和运营资料；**运营管理**处理商家、顾客、门店、线索与团购审核；**财务管理**处理套餐、订阅、订单、支付、退款、结算与卡密；**系统管理**查看审计/安全信息并维护系统配置与 AI 策略。另有两项默认关闭的高敏权限：**查看完整客户联系方式**（`customer_contact_view`）和**导出客户/订单数据**（`customer_order_export`）。导出还必须具备相应的只读/运营或财务模块权限；导出权限不会自动授予查看明文联系方式的权限。管理员账号和角色的创建、修改与停用始终仅限 `super_admin`，普通账号即使获得“系统管理”也不能管理管理员账号。

权限在每次管理 API 请求时从数据库读取，不依赖登录时缓存的角色。管理员 JWT 携带由服务端密钥签名的凭证版本，绑定持久化 `auth_version`、当前密码哈希、账号状态、角色分配和角色权限；每个管理员请求都会与数据库现状比对。密码重置/恢复、账号状态或角色/权限变化都会在同一事务中递增版本，旧 token 立即且不可逆地失效，需重新登录。该版本不依赖秒级 JWT 时间戳。新安装 schema v3 增加 `admin_users.auth_version`；部署新代码前应确认数据库结构已按对应安装/迁移流程更新。升级后，缺少新版本声明的既有管理员 JWT 会被拒绝，所有管理员需重新登录一次。角色权限采用允许列表，普通管理员未分配的权限默认为拒绝，未登记到后端路由映射的管理端点也会拒绝访问。旧的 `dashboard,users,packages...` 字符串不是新权限代码，不会自动转成新授权；超管仍保持全权，普通角色需由超管在“账号与权限”页面明确配置。

## 客户联系方式与数据导出

平台客户档案、用户目录和后台订单列表默认只返回脱敏手机号/邮箱；支付、退款、结算预览等关联订单改用最小字段白名单，避免从嵌套模型绕过默认遮罩。获准的管理员在客户档案或订单页面点“查看完整联系方式”后，前端才会请求明文；后端仍会再次校验 `customer_contact_view`，并在响应前写入敏感读取审计。权限不足或审计写入失败时，明文不会返回。

客户档案和订单/订阅营收下载均通过后端 XLSX 导出接口完成，不再由浏览器把已加载数据自行拼成文件。导出需有 `customer_order_export` 以及对应模块权限，导出事件在文件开始发送前写入审计。导出默认包含脱敏联系方式；只有同时具备 `customer_contact_view`、并在页面开启完整联系方式显示时，导出文件才会包含明文。单次导出最多 10,000 条，超限时文件会附带说明行，提示缩小筛选范围后重试。商家自己的订单履约详情仍按租户边界提供其业务所需联系方式，不受平台管理员字段权限改动影响。

## 恢复已有超管密码

项目不提供公开或未登录的超管密码重置接口。需要在部署代码所在机器的交互式终端运行恢复命令；它会隐藏密码输入并要求二次确认，只更新数据库中**已存在且当前角色仍为 `super_admin`** 的账号密码哈希，不创建账号，也不修改角色或启停状态。密码不会回显或写入应用日志。

本地开发环境示例（从包含 `.env` 的项目目录运行）：

```bash
go run ./cmd/admin-recover -username admin
```

生产环境默认拒绝。如需在生产主机**本机**恢复，必须显式确认：

```bash
go run ./cmd/admin-recover -username admin -allow-production
```

无论是否显式确认，命令只接受 MySQL 的 `127.0.0.1`、`[::1]` 或 Unix socket 目标；远程主机名/IP 一律拒绝。生产恢复需要具备部署主机的受控 shell 权限，并确认本机配置指向预期数据库。不要把密码放入命令行参数、环境变量或工单/聊天记录。
