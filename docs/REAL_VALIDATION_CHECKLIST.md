# 真实样本与上线环境验证清单

> 本轮业务流程仅使用本地 SQLite 和虚构商家/链接做合成验证；另有隔离 MySQL 8.0.46 的空模型库 `AutoMigrate` 与特定 2026-11-13 迁移顺序/重跑验证。没有访问真实商家、生产数据库、外部平台 API、支付渠道或真实 AI provider；这些合成验证不代表旧库升级或真实业务验证已通过。

## P0：真实交易与团购入口的业务正确性

| 验证项 | 需要准备 | 验收证据 |
| --- | --- | --- |
| 商家/门店真实团购链接、权限与审核 | 经商家授权的测试门店；确认抖音、美团/大众点评实际落地页、账号权限与链接归属 | 商家 A/B 隔离检查；链接是否允许后台审核、暂停/恢复；目标 URL 修改后批准失效；完整后台审核与审计记录 |
| 官方订单、退款、核销数据与字段映射 | 平台授权、官方 API 文档/资质、脱敏样本或沙箱数据 | 订单状态、退款状态、核销状态、时间、金额、商家/门店/商品 ID 映射逐字段核对；重复、延迟、缺字段、撤销等异常案例 |
| 支付回调、到账确认与退款 | 沙箱商户号、回调域名、签名/证书、退款沙箱和对账账号 | 签名校验、幂等、回调重放、金额不一致、超时/重复通知；订单、商家实收和平台订阅收入不得混账；真实资金动作另需审批 |
| 真实商家审核运行 | 至少一组获授权的商家/门店样本和负责审核人员 | 规则误判、审核理由、处理时限、申诉/改链流程、管理员身份和前后状态审计均可追溯 |

## P1：部署、数据恢复与访问安全

| 验证项 | 需要准备 | 验收证据 |
| --- | --- | --- |
| 数据库迁移（旧库升级当前阻塞） | 具体旧版本/提交对应的 schema-only 基线（或在隔离空库生成的旧版结构）、目标 MySQL 版本、备份后的隔离副本；无需真实商家数据 | 先确认旧基线与已执行迁移状态，再按明确版本计划升级副本；核对索引、唯一键、默认值、数据不变量与回滚/恢复路径。基线缺失时，旧库升级标为未支持，不执行两处历史迁移目录，也不在生产库试跑 |
| 备份与恢复演练 | 目标环境的备份存储、权限和保留策略 | 从备份恢复到隔离环境，记录耗时、恢复点、文件校验和；验证恢复后登录、订单、审计可读 |
| 角色权限与隐私要求 | 商家、平台管理员、法务/隐私负责人参与；确认收集目的和保留期限 | 商家跨租户访问测试、字段最小化、用户告知/同意、删除/导出流程、日志访问边界和数据留存策略 |
| 正式域名、HTTPS、限流与日志 | 预发布域名、证书、监控/告警配置 | HTTPS/CORS、登录与敏感接口限流、日志脱敏、错误告警、密钥轮换与权限检查 |

## AI 功能接入前后的验证顺序

1. 先用合成数据验证 provider adapter、超时、失败响应、禁用默认实现和无外呼保证；不得在演示中把模板内容标为 AI 结果。
2. 先确认商家授权和数据用途，再逐字段定义订单、退款、商品、核销数据的来源、统计口径、时间范围和隔离规则。
3. 供应商凭据只放在批准的密钥管理位置；确认隐私/合规、数据出境/供应商处理条件和费用上限，后台不得收集或明文保存 API Key。
4. 记录每次请求使用的授权数据上下文及来源、provider/模型/提示版本、结果、耗时、失败、token/成本与审计主体，并确定留存/删除规则。
5. 经商家明确同意后，先以脱敏、有限范围的真实样本做人工质量评估；记录事实错误、无依据结论、成本与延迟，不自动放开所有商家。
6. 活动、优惠、改价、发券、资金或公开发布动作必须由商家明确确认；先产生可编辑草稿，不能由模型自动执行。

## 本轮合成测试结果

`TestSyntheticMerchantSubmitToAdminReviewAuditLoop` 使用内存 SQLite 和虚构的商家/门店/链接覆盖：精确白名单自动通过、未知域名自动拒绝、域名家族内模糊链接与短链进入人工队列、管理员有理由通过/拒绝、管理员不能绕过自动拒绝、仅批准链接可跳转，以及点击计数和前后状态审计。该测试不发起外部网络请求，不调用支付、平台或 AI API。
